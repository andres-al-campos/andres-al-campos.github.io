# Portfolio

A portfolio where someone deciding whether to work with Alex can see what each tool does
in a few seconds, and go to the code.

## Principles

How the site ought to be, so a session can decide a case nobody has met yet. Each one
earns its place by deciding Calls: the rulings in `features/`, which end by naming the
principle they apply. Listed in the order they were written; when two disagree on a
case, the owner decides and the winner moves up. The hook in `hooks/` starts each with
the time and the site's version (`VERSION`) when it was made or reworded.

- 2026-10-22 02:03, 1.0.0. **The tool at its best, as it is.** A card shows the real tool at its best moment,
  doing everything it can and nothing it can't, at its real size. A reader judges from a
  still and a few seconds of clip, so a first frame undersells the tool and an enlarged
  or invented one oversells it.
- 2026-10-22 02:03, 1.0.0. **Only the subject draws the eye.** One thing moves or stands out at a time, and it's
  what the reader is already looking at. Everything else is removed or blends in,
  explanations included once they've done their job. A moving picture beside text makes
  the text hard to read, and anything that stands out takes attention it hasn't earned.
- 2026-10-22 02:03, 1.0.0. **Theirs to use.** What the reader aims at or uses stays theirs: it holds still, the
  one link on a thing is marked where it is, the rest selects like text, and where the
  platform's own tool does it better, theirs wins. Bad design feels like fighting the
  controls; the reader should only be dealing with the tool they came to see.
